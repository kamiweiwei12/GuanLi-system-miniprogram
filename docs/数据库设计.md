## 命名规范

| 对象 | 规范 | 示例 |
|---|---|---|
| 数据库名 | 小写 + 下划线 | `inspection_db` |
| 表名 | 小写 + 下划线，单数形式 | `inspection_record` |
| 字段名 | 小写 + 下划线 | `device_name` |
| 主键 | 统一使用 `id`，自增 BIGINT | `id BIGINT AUTO_INCREMENT` |
| 索引名 | `idx_表名_字段名` | `idx_record_user_id` |
| 创建时间 | 统一 `created_at` | `created_at DATETIME DEFAULT CURRENT_TIMESTAMP` |
| 更新时间 | 统一 `updated_at` | `updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP` |

---

## 表设计原则

| 原则 | 说明 |
|---|---|
| 主键 | 所有表必须有自增主键 `id` |
| 时间戳 | 业务表必须有 `created_at` 和 `updated_at` |
| 软删除 | 业务表使用 `is_deleted` 标记，不物理删除 |
| 字符集 | 统一 `utf8mb4` |
| 索引 | 为高频查询字段建立索引 |
| 外键 | 不使用物理外键，由应用层保证数据一致性 |
| YAGNI | 只设计当前需求明确的字段，不预留未来可能用到的字段 |

## 数据表

### 已有表（当前项目中已存在）

#### inspection_record（巡检记录表）✅ 当前已有

##### 业务字段（保留为历史快照）

| 字段名 | 类型 | 约束 | 说明 | 需求来源 |
|---|---|---|---|---|
| department | VARCHAR(100) | NOT NULL | 部门 | 员工填写"部门"，作为历史快照保存 |
| employee_name | VARCHAR(50) | NOT NULL | 姓名 | 员工填写"姓名"，作为历史快照保存 |
| phone_number | VARCHAR(20) | NOT NULL | 手机号 | 员工填写"手机号"，作为历史快照保存 |
| area | VARCHAR(200) | NOT NULL | 巡检区域 | 员工填写"区域" |
| inspection_time | DATETIME | NOT NULL | 巡检时间（业务时间） | 员工填写"日期"；与 created_at 区分以支持补录 |
| device_name | VARCHAR(200) | NOT NULL | 设备名称 | 员工填写"设备名称" |
| result | TINYINT | NOT NULL | 巡检结果状态码 | 员工填写"巡检结果"；固定编码便于统计 |
| description | TEXT | NULLABLE | 详细描述 | 员工填写"详细描述" |

##### 系统字段

| 字段名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT | PK, AUTO_INCREMENT | 主键 |
| user_id | BIGINT | NOT NULL, DEFAULT 0 | ✅ 提交用户 ID，关联 sys_user.id（0=历史数据） |
| created_at | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 记录创建时间 |
| updated_at | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP ON UPDATE | 记录更新时间 |
| is_deleted | TINYINT(1) | NOT NULL, DEFAULT 0 | 软删除标记（0=正常, 1=已删除） |

##### result 状态码约定

| 状态码 | 含义 |
|---|---|
| 0 | 正常 |
| 1 | 故障 |
| 2 | 隐患 |

状态码与显示文本的映射由程序常量管理。

### 用户体系表（Phase 5 — 已完成）

#### sys_user（系统用户表）✅ 已完成

| 字段名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT | PK, AUTO_INCREMENT | 主键 |
| openid | VARCHAR(64) | NOT NULL, UNIQUE | 微信 openid（身份认证入口） |
| username | VARCHAR(50) | NOT NULL | 用户名 |
| phone | VARCHAR(20) | NULLABLE | 手机号 |
| department_id | BIGINT | NULLABLE | 部门 ID，关联 sys_department.id |
| role_id | BIGINT | NOT NULL | 角色 ID，关联 sys_role.id |
| status | TINYINT | NOT NULL, DEFAULT 1 | 状态（0=禁用, 1=正常） |
| nickname | VARCHAR(100) | NULLABLE | 微信昵称 |
| avatar_url | VARCHAR(500) | NULLABLE | 微信头像 |
| created_at | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 注册时间 |
| updated_at | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP ON UPDATE | 更新时间 |
| is_deleted | TINYINT(1) | NOT NULL, DEFAULT 0 | 软删除 |

**索引**：
- `UNIQUE INDEX idx_user_openid (openid)` — openid 唯一

> **设计说明**：微信 openid 作为身份认证入口，但不等同于企业员工身份。一个 openid 绑定一个 sys_user 账号，sys_user 拥有独立的企业角色、部门归属和权限。

#### sys_role（系统角色表）✅ 已完成

| 字段名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT | PK, AUTO_INCREMENT | 主键 |
| role_name | VARCHAR(50) | NOT NULL | 角色名称（普通员工 / 部门管理员 / 系统管理员） |
| role_code | VARCHAR(30) | NOT NULL, UNIQUE | 角色编码（EMPLOYEE / DEPT_ADMIN / ADMIN） |
| created_at | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 创建时间 |

**预置数据**：

| role_code | role_name | 说明 |
|---|---|---|
| EMPLOYEE | 普通员工 | 只能查看/修改自己的巡检记录 |
| DEPT_ADMIN | 部门管理员 | 可查看本部门所有记录 |
| ADMIN | 系统管理员 | 可查看全部记录，管理用户 |

> **设计说明**：不使用 `role=0/1` 硬编码，采用独立角色表。支持未来扩展更多角色类型，通过 role_code 程序常量绑定权限逻辑。

#### sys_department（部门表）✅ 已完成

| 字段名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT | PK, AUTO_INCREMENT | 主键 |
| dept_name | VARCHAR(100) | NOT NULL | 部门名称 |
| parent_id | BIGINT | NULLABLE, DEFAULT 0 | 上级部门 ID（0=顶级部门） |
| created_at | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP ON UPDATE | 更新时间 |
| is_deleted | TINYINT(1) | NOT NULL, DEFAULT 0 | 软删除 |

> **设计说明**：当前阶段只实现基础部门表（部门名称 + 简单上下级关系），不实现复杂组织树。`sys_user.department_id` 依赖此表。复杂层级扩展（如多级组织）留待未来迭代。

#### sys_token（认证令牌表）✅ 已完成

| 字段名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT | PK, AUTO_INCREMENT | 主键 |
| user_id | BIGINT | NOT NULL | 用户 ID，关联 sys_user.id |
| token | VARCHAR(64) | NOT NULL, UNIQUE | 令牌值（UUID） |
| expire_time | DATETIME | NOT NULL | 过期时间 |
| created_at | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 创建时间 |

**索引**：
- `UNIQUE INDEX idx_token_value (token)` — token 查询
- `INDEX idx_token_user_id (user_id)` — 按用户查询

> **设计说明**：当前采用数据库 Token 方案（UUID + 过期时间），简单可控。未来可替换为 Redis/JWT，不影响 UserContext 设计（UserContext 只依赖 userId 和 role，不耦合 Token 存储方式）。

## 数据迁移说明

当用户体系表创建后，现有 `inspection_record` 数据：

- `user_id = 0` — 表示"未归属的历史记录"
- 后续新增的记录将写入实际的 `user_id`

不需要对现有数据进行批量迁移（历史记录不追溯用户归属）。
