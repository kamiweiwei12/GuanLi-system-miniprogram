# 新环境部署与访问说明

> 📌 面向将项目迁移到新电脑 / 新服务器的开发者，覆盖从 git clone 到完整可用的全流程。
> 本文档不涉及代码修改，仅说明配置和操作。

---

## 1. Docker 新环境部署

### 1.1 部署流程

```bash
# 1. 克隆项目
git clone <仓库地址>
cd miniprogram-1

# 2. 配置环境变量
cp docker/.env.example .env
# 编辑 .env 文件, 填入 [必填] 项
#    MYSQL_ROOT_PASSWORD=your_root_password
#    MYSQL_USER=inspection
#    MYSQL_PASSWORD=your_app_password
#    SPRING_DATASOURCE_USERNAME=inspection
#    SPRING_DATASOURCE_PASSWORD=your_app_password

# 3. 启动所有服务
docker compose up -d
```

### 1.2 验证启动状态

```bash
docker compose ps
```

**预期输出** (3 个服务均为 `Up`)：

| 服务 | 容器名 (自动生成) | 说明 |
|---|---|---|
| mysql | `miniprogram-1-mysql-1` | MySQL 8.0 数据库，端口 3306 |
| backend | `miniprogram-1-backend-1` | Spring Boot API，**不暴露宿主机端口**，仅 nginx 可访问 |
| nginx | `miniprogram-1-nginx-1` | Nginx 反向代理，端口 80 |

> 容器名由 Docker Compose 根据项目目录名自动生成。如果目录名不是 `miniprogram-1`，容器名会有变化，建议使用 `docker compose ps` 查看实际名称。

### 1.3 访问架构

```
浏览器
  ↓ http://服务器IP/
nginx:80
  ├── /         → admin Vue3 前端静态页面
  ├── /api/     → backend:8080 (反向代理)
  └── /uploads/ → backend:8080 (图片文件)
```

> ❌ **不要** 直接访问 `http://localhost:8080`，backend 不暴露端口给宿主机。

### 1.4 停止服务

```bash
docker compose down         # 停止，保留数据
docker compose down -v      # 停止并清空数据库 (⚠ 不可逆)
```

## 2. 数据库初始化说明

### 2.1 首次启动自动初始化

`docker-compose.yml` 中挂载了初始化脚本：

```
./database/init.sql → /docker-entrypoint-initdb.d/01-init.sql
```

首次启动且 **MySQL 数据目录为空** 时，以下 7 张表会自动创建：

| 表名 | 说明 |
|---|---|
| `sys_role` | 系统角色 (EMPLOYEE/DEPT_ADMIN/ADMIN) |
| `sys_department` | 部门 |
| `sys_user` | 系统用户 |
| `sys_token` | 认证令牌 |
| `inspection_record` | 巡检记录 |
| `inspection_image` | 巡检图片 |
| `sys_operation_log` | 操作日志 (Phase 14) |

### 2.2 已有 volume 不会重复初始化

如果 `mysql_data` volume 已存在 (即之前启动过)，`init.sql` **不会** 再次执行。因此生产环境重启不会丢失数据。

### 2.3 如需全新初始化

```bash
docker compose down -v    # ⚠ 删除 volume，清空所有数据库数据
docker compose up -d      # 重新初始化
```

## 3. 默认管理员账号查看方法

> 新环境启动后，不要猜测密码。通过数据库直接查询管理员信息。

### 3.1 进入 MySQL

```bash
docker compose exec mysql mysql -u inspection -pinspection_pwd_2026 inspection_db
```

> 如果 `.env` 中密码不同，替换 `-pinspection_pwd_2026` 为实际密码。

### 3.2 查看管理员

```sql
-- 查看所有用户
SELECT id, username, openid, role_id FROM sys_user;

-- 查看所有角色
SELECT id, role_name, role_code FROM sys_role;
```

**输出示例**：

```
id | username    | openid          | role_id
1  | 系统管理员   | admin_default   | 3
```

- `role_id=3` → ADMIN (系统管理员)
- `role_id=2` → DEPT_ADMIN (部门管理员)
- `role_id=1` → EMPLOYEE (普通员工)

### 3.3 管理员 Token

`database/init.sql` 中预置的管理员 Token：

```
admin-setup-token
```

该 Token 绑定 `sys_user.id=1` 的管理员，可直接用于 API 和 Admin 后台登录。

### 3.4 新增管理员

如需新增管理员，通过 SQL：

```sql
INSERT INTO sys_user (openid, username, role_id, status)
VALUES ('admin_new', '新管理员', 3, 1);
INSERT INTO sys_token (user_id, token, expire_time)
VALUES (LAST_INSERT_ID(), 'your-new-token', '2099-12-31 23:59:59');
```

或通过 Admin 后台 "用户管理" 页面创建用户并设置角色。

## 4. Admin 后台访问方式

### 4.1 生产环境

浏览器访问：

```
http://服务器IP/
```

### 4.2 请求流程

```
浏览器打开 http://IP/
  ↓
nginx 返回 admin 前端页面 (Vue3 SPA)
  ↓
前端发起 API 请求 (如 /api/v1/dashboard)
  ↓
nginx 反向代理到 backend:8080
  ↓
返回 JSON 数据
```

> ❌ **不要** 直接访问 `http://localhost:8080`，backend 不暴露端口。

## 5. Admin 登录流程说明

### 5.1 管理员登录

Admin 前端使用 Token 登录方式：

1. 管理员打开 Admin 后台 → 进入登录页
2. 输入 Token：`admin-setup-token`
3. 前端调用 `GET /api/v1/statistics` 验证 Token 有效性
4. 验证通过 → 保存 Token 到 localStorage
5. 后续所有 API 请求自动携带：

```
Authorization: Bearer admin-setup-token
```

### 5.2 Token 过期处理

- Token 过期后，后端返回 401
- 前端自动清除 Token 并跳转登录页
- 重新输入有效 Token 即可恢复访问

## 6. 微信小程序连接方式

### 6.1 配置 API 地址

打开 `miniprogram/config/env.ts`：

```typescript
const IS_DEV = true;  // true=开发环境, false=生产环境
const DEV_HOST = 'http://localhost:8080';
const PROD_HOST = 'https://your-domain.com';
```

### 6.2 生产环境配置

```typescript
const IS_DEV = false;
const PROD_HOST = 'https://your-domain.com';  // 替换为实际服务器地址
```

### 6.3 真机调试注意事项

> ⚠️ 手机微信 **无法** 访问电脑 `localhost`。

真机调试方案：

| 方案 | 说明 |
|---|---|
| 部署到服务器域名 | 最推荐，配置 `PROD_HOST` 为实际域名 |
| 局域网 IP | 手机和电脑同一 WiFi，`PROD_HOST` 设为电脑局域网 IP (如 `http://192.168.1.100`) |
| 微信开发者工具预览 | 开发者工具内置代理，无需配置 |

## 7. 小程序首次登录流程

```
用户打开小程序
  ↓
app.ts onLaunch
  ↓
wx.login() → 获取临时 code
  ↓
POST /api/v1/login { code }
  ↓
backend 调用微信接口 → openid
  ↓
查询 sys_user (WHERE openid = ?)
  ├── 已存在 → 更新登录信息
  └── 不存在 → INSERT 新用户 (默认 role_id=1 EMPLOYEE)
  ↓
创建 sys_token (UUID, expire_time=7天)
  ↓
返回 { token, userId, roleCode }
  ↓
小程序保存 token 到 storage
  ↓
后续请求携带: Authorization: Bearer {token}
```

### 7.1 绑定管理员身份

如需将某个微信账号设为管理员：

```sql
UPDATE sys_user SET role_id = 3 WHERE openid = '微信用户的openid';
```

用户的 openid 可从 `sys_user` 表或登录日志中获取。

## 8. 上传图片说明

### 8.1 上传流程

```
小程序
  ↓ wx.uploadFile
POST /api/v1/upload/image
  ↓
backend FileUploadController
  ↓ 保存到 uploads volume
返回路径: /uploads/yyyy/MM/dd/UUID.jpg
  ↓
数据库 inspection_image 记录关联
```

### 8.2 图片访问方式

| 方式 | 路径 | 状态 |
|---|---|---|
| 安全访问 (推荐) | `GET /api/v1/file/{imageId}` | ✅ Phase 14 新增，经过 AuthInterceptor |
| 兼容访问 | `GET /uploads/*` | ⚠️ 旧方式，未来移除 |

> 新功能应使用 `/api/v1/file/{id}` 获取图片，旧 `/uploads/*` 仅兼容历史数据。

## 9. 常用排查命令

### 9.1 查看日志

```bash
docker compose logs -f backend    # 后端实时日志
docker compose logs -f nginx      # Nginx 实时日志
docker compose logs --tail=100    # 最近 100 行日志
```

### 9.2 进入数据库

```bash
docker compose exec mysql mysql -u inspection -p inspection_db
```

### 9.3 检查接口

```bash
# 健康检查
curl http://localhost/api/v1/ping

# 查看所有统计
curl -H "Authorization: Bearer admin-setup-token" http://localhost/api/v1/statistics/overview
```

### 9.4 查看容器状态

```bash
docker compose ps              # 所有服务状态
docker compose exec backend java -version  # 查看 Java 版本
```

### 9.5 重启单个服务

```bash
docker compose restart backend
docker compose restart nginx
```

## 10. Windows 部署注意事项

### 10.1 SQL 导入必须使用重定向

❌ **禁止使用 PowerShell 管道导入：**

```powershell
Get-Content database\test-data.sql | docker compose exec -T mysql mysql ...
```

原因：PowerShell 会将 UTF-8 文件转为 UTF-16LE 传给 Docker，导致中文乱码。

✅ **推荐方式：**

```cmd
docker compose exec -T mysql mysql --default-character-set=utf8mb4 -u inspection -p inspection_db < database\test-data.sql
```
