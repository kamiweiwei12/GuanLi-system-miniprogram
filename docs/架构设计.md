## 架构分层

采用四层结构：Controller → Service → Mapper → Database。

| 层级 | 目录 | 职责 | 依赖方向 |
|---|---|---|---|
| Controller | `controller/` | 接收 HTTP 请求、参数校验、调用 Service、返回响应 | Service 接口 |
| Service | `service/` + `service/impl/` | 业务逻辑、事务管理 | Mapper 接口 |
| Mapper | `mapper/` | 数据库操作（CRUD） | Entity |
| Entity | `entity/` | 数据库表映射 | 无 |

### 数据传输对象

| 对象类型 | 目录 | 用途 |
|---|---|---|
| DTO | `dto/` | 接收前端请求参数 |
| VO | `vo/` | 返回给前端的视图数据 |
| Entity | `entity/` | 数据库表映射 |

### 跨层数据传递约束

- Controller 只接收 DTO，只返回 VO
- Entity 只在 Service 和 Mapper 之间传递，不暴露到 Controller
- Service 接口与实现分离（`service/` 定义接口，`service/impl/` 实现）
- Controller 不直接操作 Mapper

## 数据流向

```
用户操作（小程序/Web）
        │
        ▼
  ┌─────────────┐
  │  Controller  │  ← 接收 HTTP 请求，DTO 参数校验
  └──────┬──────┘
         │  DTO
         ▼
  ┌─────────────┐
  │   Service    │  ← 业务逻辑处理、事务边界
  └──────┬──────┘
         │  Entity
         ▼
  ┌─────────────┐
  │   Mapper     │  ← SQL 执行
  └──────┬──────┘
         │
         ▼
  ┌─────────────┐
  │   MySQL      │
  └──────┬──────┘
         │  Entity
         ▼
  ┌─────────────┐
  │   Service    │  ← 组装返回数据
  └──────┬──────┘
         │  VO
         ▼
  ┌─────────────┐
  │  Controller  │  ← Result<VO> JSON 响应
  └─────────────┘
```
